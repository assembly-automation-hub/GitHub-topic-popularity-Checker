How it works

Everything happens in your browser tab.

  1. 1 Normalize. Each line is trimmed, leading # characters are stripped, text is lowercased, and duplicates are removed while keeping first-seen order.
  2. 2 Validate. Slugs must be 1–50 lowercase alphanumeric or hyphen characters and cannot start or end with a hyphen. Invalid entries are rejected before any request.
  3. 3 Query. One GET /search/repositories?q=topic:<slug> call per uncached topic, sequentially, with a 10-second timeout and a single retry on transient 502/503/504.
  4. 4 Pace. Rate-limit headers are read after each response: a small baseline delay while quota is healthy, spread-out pacing as it runs low, and a hard stop on fatal auth or quota errors.
  5. 5 Cache. Successful counts live in an in-memory map for five minutes, so re-checking the same batch is instant. Reloading the page clears it.

Privacy. The page policy allows connections only to api.github.com, blocks third-party scripts and styles, and sends no referrer. An optional token is used for the current batch and never persisted.
